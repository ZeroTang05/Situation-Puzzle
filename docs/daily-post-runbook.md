# 每日内容日更 · 执行手册（Runbook）

给每天 22:00 自动运行的 agent 会话用。**照着做，不用改脚本。**
工作目录固定为 `E:\tzy\github\jev-turtle-soup`，所有命令都在该目录执行。

## 背景

这是一个图文平台上的连载推理谜题账号，每天发一篇笔记，内容三件套：

1. **今日汤面图** —— 今天这道题的题面（不含答案）
2. **昨日汤底图** —— 昨天那道题的完整答案（第 1 天没有这一张）
3. **正文文案** —— 今日题目 + 作者声明 + "答案在下一篇笔记揭晓"

版式是**统一背景的卡片流**：全系列共用两张无文字暗黑背景图——
汤面用冷蓝走廊（`data/xhs/assets/background-face.jpg`），
汤底用红光开门（`data/xhs/assets/background-bottom.jpg`），两者一眼能区分开。

每张卡片的**正文字数动态均衡**：脚本按总量算卡片数，再把正文均分到各张
（每张大致 100～130 字），所以不会出现"一张图只有十几个字"的碎卡；
卡尾字号自动缩放，右下角标 `页码/总张数`。

题目按 `data/library.json` 的顺序依次推进（446 题）。题号进度由脚本
`data/xhs/state.json` 管理，**任何情况下都不要手动改这个文件**。

风格设定（已定，不要临场发挥）：

| 项 | 设定 |
| --- | --- |
| 文案口吻 | 轻松互动：口语化、可带 emoji、玩梗，结尾引导评论区猜 |
| 画面风格 | 暗黑恐怖插画（汤面冷蓝 / 汤底红光，两张固定背景图，已定稿） |
| 单图字数 | 正文动态均衡，每张约 100～130 字，脚本自动切分，不要自己截断 |
| 账号署名 | 不出现账号名 |

## 五步

### 1. 取素材事实

```bash
node scripts/xhs-daily.mjs plan --date <今天日期 YYYY-MM-DD，按本机时间>
```

输出 JSON，重点字段：

- `today.title` / `today.story` —— 今日题面
- `today.statement` —— 今日的作者声明（脚本从 `data/sources.md` 自动取，正文里已填好）
- `prev.title` / `prev.answer` —— **昨日**的题名与完整答案（汤底卡片的内容）
- `prev` 为 `null` 表示这是第 1 天，没有汤底卡片
- `requestExample` —— 请求稿格式

> 今日的答案**不会**出现在 plan 输出里。剧透 = 破坏连载。

### 2. 写文案三段

| 字段 | 内容 |
| --- | --- |
| `hook` | 开场白 1-2 句，轻松口语，可带 1 个 emoji |
| `guide` | 结尾引导评论区的 1-2 句 |
| `hashtags` | 4-6 个话题标签 |

- 轻松互动口吻，别写成散文。
- `guide` **只写互动引导**，不要重复"答案在下一篇笔记"或"图几"——这两句脚本已经填好。
- **图序（"图二"之类）不要自己写**。你写文案时还不知道今天会渲染出几张图，写死会指错
  （446 题里有 70 天的汤面不止占 1 张，汤底就从图三开始了）。脚本在渲染后会按真实张数
  自动填好汤底图序。
- 如果你确实想在自己的句子里引用汤底图序，写占位符 `{{prevImageStart}}`，脚本会替换成
  "图二"或"图二、图三"。
- 今日题面正文、作者声明、"答案在下一篇笔记揭晓"由脚本从题库事实自动填充，**你只写这三段**。

### 3. 写请求稿

路径 `data/xhs/requests/<日期>.json`：

```json
{
  "date": "<日期>",
  "copy": {
    "hook": "...",
    "guide": "...",
    "hashtags": ["#...", "#..."]
  }
}
```

### 4. 执行

```bash
node scripts/xhs-daily.mjs run --input data/xhs/requests/<日期>.json
```

脚本依次完成：按总量动态切分卡片 → 用对应背景图 + 真实排版渲染出
`01-汤面.png`、`02-汤底.png`… → 产出 `文案.txt`、`meta.json` → 推进题号进度。

- 输出的 `cards` 数组里每张都有 `chars`（该卡正文字数）、`totalChars`（含标题）和
  `page`（页码/总张数），交付时按 `page` 顺序给用户。
- `warnings` 非空要读一下：一般是题目过长导致张数逼近 18 张上限（小红书单篇最多 18 张），
  此时在交付说明里提醒用户。
- 失败时读 stderr 的报错定位原因，**修一次再重试**。
- 仍失败就把错误原样告诉用户，并明确说明"进度未推进"。
- 同一天重跑是幂等的（同一个题号、同一批卡片），所以重试永远安全。

### 5. 交付

- 卡片图用 `type=image`，文案用 `type=file`，`src` 一律用**绝对路径**。
- 用一两句说明：第几天、今天题目名、昨天那碗汤底是哪题、共几张图。
- 最后附一句明日预告（不要剧透明日题目内容）。

## 其他常用命令

```bash
node scripts/xhs-daily.mjs status        # 到第几天、还剩几题
node scripts/xhs-daily.mjs reset --index N   # 手动回到第 N 题（1 起），慎用
node scripts/xhs-daily.mjs run --input <请求.json> --dry-run   # 试跑，不推进进度
node scripts/xhs-daily.mjs background --kind face|bottom [--force]   # 重新生成背景图（除非用户要求，别动）
```

排版参数（尺寸/配色/单图字数上限/背景图路径与提示词）在 `data/xhs/config.json`，
文案模板在 `data/xhs/copy-template.txt`，改完不用动脚本。

流水线设计细节见 `docs/xhs-daily-pipeline.md`。
