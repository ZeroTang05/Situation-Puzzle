# 题目点赞、点踩与作者署名

更新：2026-09-27。本文定义产品与实现要求，代码尚待开发。评价和署名规则以本文为准。

## 1. 产品目标与默认规则

用户已确认：自带题目与 UGC（用户投稿）统一支持点赞、点踩；题库可按受欢迎程度排序；投稿作者可选择署名或匿名，前端展示其选择。作者可以看到作品获得的反馈。

以下为首发默认规则：登录后投票，每账号每题一票，可切换或取消；不要求多人游玩记录；作者不能给自己的作品投票；默认按最新发布浏览，可切换到“最受欢迎”。署名按每篇作品独立设置，新稿默认匿名，作者主动开启署名。这些默认值不改变单人匿名游玩和本地记录规则。

## 2. 点赞与点踩

- 所有已发布、可访问的自带题目和投稿题目使用同一套规则。未登录用户可查看总数，点击投票时登录，成功后返回原题，保留单人页面的本地进度。
- 每账号每个作品只有一个选择：赞、踩、未投票。再次点击当前选项取消，点击另一个选项切换。换题目版本、换设备、玩多个房间均不能增加票数。
- 允许登录用户直接评价题目，无须提交房间编号、单人凭证或游玩历史。投票是用户主动提交的独立数据：保存账号与作品的投票关系，不据此创建单人会话、对话或“已玩”记录。
- 作者不能给自己的作品投票，匿名作者也按内部归属校验。每次写入检查登录、账号状态、作品状态和归属，前端隐藏按钮不能替代服务端校验。
- 公开展示点赞数、点踩数；只向本人返回自己的投票选择。投票人的名单、邮箱、账号编号不公开。
- 点踩表达对题目的评价；内容侵权、违规和判题错误继续使用举报入口。首发不增加公开文字评论。
- 成功写入后更新当前页计数；请求失败保留原状态并允许重试。同一账号多设备同时操作时，以服务端最后提交状态为准，刷新后统一。

## 3. 受欢迎排序

首发采用清楚可解释的规则：**受欢迎得分 = 点赞数 − 点踩数**。选择“最受欢迎”时，依次按得分降序、点赞数降序、首次发布时间降序、作品 ID 升序排列。相同票数下顺序稳定；后台与前端使用同一规则。

例如：30 赞、5 踩的得分为 25；10 赞、0 踩的得分为 10，前者排在前面。无投票作品得分为 0。该规则衡量累计净支持量，新题还可通过“最新发布”被发现。作品普通改版继续累计原作品投票，后台可按投票时版本分析反馈。

排序先应用关键词、难度、主题等筛选，再在命中作品中排序。只包含已发布且可访问作品，不因票数低自动下架。点赞数、点踩数和排序得分由服务端计算，客户端不能提交。

列表采用包含排序字段与作品 ID 的游标。投票变化可能让题目在翻页时移动，客户端按作品 ID 去重；刷新列表重新获取最新顺序。首发不承诺跨多次分页冻结整个排行榜。

## 4. 作者署名与匿名

- 投稿编辑页提供“匿名发布 / 展示署名”，并展示与公开页面一致的预览。选择署名时填写 1～30 个字符的展示名，去除首尾空格，以纯文本显示。邮箱、登录名不自动作为署名。
- 署名是作品级设置，用户可以让不同作品采用不同方式。公开显示“作者：展示名”或“匿名作者”。署名不要求实名，也不宣称身份认证。
- 真实 `authorUserId`（作者账号编号）始终保存在服务端，用于作品管理、审核和禁止自投。匿名作品的公开接口、网页数据、房间快照和事件不包含作者编号、个人主页链接或可识别作者的信息。
- 游戏中的“已知答案”标记不得标注“因为是作者”；匿名作者参加自己题目的房间时，公共标记与其他已知答案玩家保持一致。
- 署名内容进入投稿审核。已发布作品改为匿名立即生效；匿名改为署名或修改展示名，经审核后公开。等待审核时保留此前公开状态。公开页面及缓存同步更新署名，历史游戏回看也读取当前公开署名设置；题目正文仍使用开局固定版本。
- 自带题目遵循实际授权中的署名要求；来源不明时不能把录入人员当作者。后台单独配置授权署名及来源。授权要求的署名保留，不允许用匿名选项覆盖法律或许可要求。
- 匿名只隐藏对外署名，作品仍在作者自己的创作中心展示；后台有权限的审核人员可以核验归属。

## 5. 页面与作者反馈

| 页面 | 展示与操作 |
| --- | --- |
| 题库列表 | 标题、作者署名或匿名、赞数和踩数；排序选项“最新发布 / 最受欢迎”；零票显示 0 |
| 题目详情 | 作者、赞与踩按钮、计数和自己的选择；没有投票时两按钮均未选中 |
| 单人及多人结算 | 对当前题投票；多人各账号独立投票，不改变其他成员的选择 |
| 创作编辑 | 署名方式、展示名、公开预览；署名审核状态与内容审核状态可辨认 |
| 我的作品 | 每题的赞数、踩数、净支持量与发布状态；作者收到反馈无需公开身份 |
| 内容后台 | 每题统计、版本信息、作者归属与公开署名、署名审核；真实投票计数不可直接手填 |

首发通过作品反馈提供成就感，不新增作者积分、勋章或奖金规则。题库排序与成员之间的游戏排名互相独立。

## 6. 数据与接口

复用 `ratings`（题目投票）表及 `(user_id,puzzle_id)` 唯一约束，统一 `value` 为 up/down（赞/踩）。记录创建、更新时间与投票时的已发布版本编号；`roundId` 不再是投票资格条件。取消使用删除投票。公开文字评论不进入本期接口。

服务端从有效投票按作品聚合 upCount、downCount、popularityScore（赞数、踩数、受欢迎得分），没有记录时均为 0。首发直接数据库聚合；实际查询性能需要时再增加统计表，不能让两个独立计数成为不同事实来源。

作品保存内部作者编号、署名模式、已批准展示名及待审署名。公共投影只含 `authorDisplay: { mode, name }`（公开署名方式与名称），匿名时 name 为 null，不返回内部归属。作者和审核员通过独立权限接口读取完整归属。

| 接口 | 行为 |
| --- | --- |
| `GET /puzzles?sort=latest\|popular` | 发布题目列表、计数、公开署名；筛选与排序组合 |
| `GET /puzzles/:id` | 题目公开信息、投票总数、公开署名；不含投票人资料 |
| `GET /ratings/:puzzleId` | 已登录用户自己的选择与最新统计，响应禁止公共缓存 |
| `PUT /ratings/:puzzleId` | `{ value: up 或 down }`；明确设置选择，同值重试不累加，返回最新本人选择与统计 |
| `DELETE /ratings/:puzzleId` | 取消本人投票；重复删除结果一致，返回最新统计 |
| 创作保存及后台审核接口 | 接收署名选项和展示名，执行归属与审核校验；匿名公开投影统一生成 |

客户端点击切换成明确的 PUT 或 DELETE 请求，不能把“切换一次”作为可被网络重试重复执行的服务器命令。公开统计与私人选择分开读取，避免公共缓存把某个用户的选择展示给别人。
