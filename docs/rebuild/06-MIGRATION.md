# 现有代码与数据迁移方案

## 1. 现状核对

核对基线 `d4fd1e4`。当前为 Next.js 单页前端、Cloudflare Worker 后端、D1 的 soups/moderation_logs/stats 三类业务表。`data/library.json` 与 `library.en.json` 各 30 条，共用题目 ID。没有账号、多人房间、支付或云端对话表。

当前单人问答存在 React 内存中，`lib/browser-progress.ts` 只保存题目进度统计，尚未保存完整本地对话。普通网页 `app/page.tsx` 直接导入中英文题库文件，包含答案；新版本应从服务端取汤面并按单人/多人规则揭晓。旧数据不能凭空补出从未保存的历史聊天。

当前 Jev 核心已有三种用途、结果选项校验和重试，值得保留。需要修正：本地阈值 0.4 与 Worker 0.5 不同、未设置请求超时、缺概率时默认为 0、对所有错误统一重试；这些行为必须按新协议改写。

当前投稿通过 AI 二元检查就发布，管理员共享 Basic 密码，作者使用 creator_token。新版本改为账号归属、机器辅助加人工发布和分角色后台。

## 3. 数据迁移映射

| 旧数据 | 新落点 | 规则 |
| --- | --- | --- |
| 中英内置 JSON | puzzles + puzzle_versions | 共用作品 ID，各自语言版本；内容散列防重复导入；author 为空或官方编辑账号 |
| D1 内置种子行 | 与 JSON 对应的导入记录 | 同 ID 与规范 JSON 对照；差异列入报告，不能静默覆盖 |
| D1 玩家投稿 | puzzles + puzzle_versions | 保留稳定 ID、时间、语言和展示署名，映射旧状态；无真实账号归属 |
| D1 moderation_logs | 历史审核记录 | 操作者标记 legacy_admin，保留旧动作与时间，不编造审核人 |
| D1 stats | 新系统重算 | 从已导入可发布题统计，不沿用边缘平台计费优化常量 |
| creator_token | 受控迁移审计材料 | 不升级成新登录凭据；不随 API 输出；默认没有自助认领功能 |
| 浏览器 `jev-browser-progress` | 本地 legacy_progress / solo_progress | 用户选择导入，在同源浏览器内执行；保留旧统计与新版精确会话的区别 |
| 旧内存聊天 | 无可恢复源 | 不生成空壳“迁移成功”记录 |

旧 UGC 的展示署名不能证明账号归属。首发由平台托管为历史投稿，作者如需认领走人工核验；单凭同名或知道题目内容不能取得编辑权限。未核实商业授权的旧内容进入待审核库，不直接公开。

数据库导入工具通过 SQLite 驱动读取 D1 导出恢复文件或正式 JSON 导出，用标准 JSON/SQL 工具处理内容；禁止正则拆分 SQL INSERT 或手写解析器。使用 staging（导入暂存区）核对，再事务写入正式表。

导入幂等键为来源、旧 ID、语言、源内容散列。生成清单：源行数、目标行数、状态分布、重复 ID、失联审核记录、题目内容散列、中英配对、提示数量和待授权数量。异常直接失败并给出具体记录，修正输入后重跑。

本地进度只在用户点击“导入旧版进度”后迁入本地新结构，完成前不删除旧键。域名沿用原站时浏览器仍可访问原存储；域名变更则提供旧站本地导出、新站本地导入，不用后台上传搬运。

## 4. 分阶段迁移与上线

1. **建立新结构。** 在新目录开发，旧代码仍可构建。独立测试数据库和域名，与生产 D1、支付订单隔离。
2. **打通题库与单人。** 导入测试题、验证真实 Jev、本地完整对话、无单人持久日志。先保留现有核心玩法价值。
3. **打通多人。** 上线账号、房间状态、持久事件、队列、后台和免费 10 次账户；通过真实多设备测试。
4. **打通赞助。** 商户完成后真实支付/退款；测试权益与正式支付记录隔离；6 元和 20 元商品契约正确。
5. **迁移演练。** 使用旧库快照做完整导入、校验和恢复；记录耗时与失败处理，生成正式切换清单。
6. **冻结旧写入。** 预告维护窗口，关闭旧投稿/审核写入，导出最终 D1 数据；记录最后更新时间和校验值，避免漏掉演练后新增投稿。
7. **正式导入。** 备份新旧数据库，在空的新正式业务库或经核验的暂存区导入。保留旧账号数为零的事实，不能自动为署名创建账号。
8. **切换域名。** 原站域名指向自有服务器；旧 `?soup=ID&lang=...` 分享链接由新前端读取并跳转题目页，保留稳定 ID。旧后台和任意公开答案接口停用。
9. **观察与验收。** 重点看注册、单人隐私、房间延迟、Jev 错误、订单授权和日志。确认负责人体验与真实业务通过。
10. **退役旧系统。** 稳定观察窗口默认 7 天后执行删除清单，撤销旧 Vercel/Worker 部署和旧密钥权限，保留受控导出备份；更新文档和导航。

正式切换由负责人安排具体时间；本次设计不操作线上服务。

## 5. 回退与不可丢失的数据

切换前记录旧部署版本、DNS 与代理配置、D1 导出和新 PostgreSQL 备份。新站尚未接收真实房间/支付写入时，可直接切回旧站并重新修复迁移。

新站已有真实房间或订单后，数据库必须继续保留，不能还原到旧快照抹掉新增数据。应用回退到兼容当前数据库的上一个新版本；必要时关闭新开房和收款入口、保留历史查询及支付回调/查单处理。旧单人站不具备赞助账务能力，不能作为整个商业系统的数据回退目标。

退款和通道查询在回退期间仍能处理；只有迁移确认前从未开放的功能才可以整体撤销。破坏性字段删除要等兼容观察期结束后再做。

## 6. 完成标准

- 新功能通过 MVP 验收，用户人工体验确认后再提交和合并。
- 所有保留题目、投稿、审核日志均有核对结果；未授权内容不可被正式游玩接口读取。
- 玩家构建包不包含题库汤底和密钥；单人只存本地，多人记录可恢复。
- 旧边缘平台代码、脚本、依赖、环境变量和文档入口全部按清单退役。
- 清理本轮临时导入副本、测试账号/授权、浏览器与进程；保留正式备份和迁移报告，不把备份误当临时产物删除。
