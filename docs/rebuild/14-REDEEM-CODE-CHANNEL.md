# 赞助码通道（零实名收款）

> 面向运营方。目的：在**微信/支付宝商户资质未开通**的前提下，让站内赞助权益
> 真的能卖出钱、且站内流程全自动。

## 一句话

微信支付 v3 的适配器已经完整实现（签名、回调验签解密、查单、关单、退款），
但商户号、APIv3 密钥与平台证书需要**商户资质 + 实名**才能开通。资质没到位之前，
站内没有任何收款入口，赞助权益一件也卖不出去。

赞助码把「收钱」这一步交给运营方用**个人收款码**完成（不需要任何平台资质），
站内只负责「发码 → 兑换 → 核销 → 发授权」，全部自动完成。

| | 微信支付 Native | 赞助码 |
| --- | --- | --- |
| 需要资质 | 微信商户号（营业执照/个体户 + 结算卡 + 实名） | **无** |
| 站内自动化 | 全自动（回调驱动） | 全自动（用户点兑换驱动） |
| 收款动作 | 用户扫码 | 运营方个人收款码（人工） |
| 到账延迟 | 秒级 | 取决于运营方何时发码 |
| 上线条件 | 商户凭据齐备 | 立刻可用 |

两条通道并存、互不影响。商户资质到位后，把凭据配进 `.env` 即可同时开微信支付。

## 价格

沿用首发口径（docs/rebuild/01-PRD.md §5）：

- 月度会员 **¥6**（600 分），有效期内不限次数开房；
- 永久会员 **¥20**（2000 分），永久不限次数开房。

单人游玩永远免费。模型成本极低（`jev-1.13` 输入 $0.042/1M token、输出免费，
单次判定约 427 输入 token ≈ ¥0.0001），因此定价远高于成本。

## 日常操作

### 1. 收款

用个人微信/支付宝收款码收款（金额 = ¥6 或 ¥20）。个人收款码不需要商户资质。

### 2. 发码

在服务器上执行（一条命令出码）：

```bash
# 月度码 ×10
docker exec situation-puzzle-api-1 pnpm --dir apps/api exec tsx src/cli/issue-redeem-codes.ts \
  --type monthly --count 10 --note "10月推广"

# 永久码 ×5，2026-12-31 过期
docker exec situation-puzzle-api-1 pnpm --dir apps/api exec tsx src/cli/issue-redeem-codes.ts \
  --type lifetime --count 5 --expires 2026-12-31T23:59:59Z
```

输出形如：

```
批量发码完成
批次号 batchId : B20261020-3F9A21
商品           : 月度会员（monthly）
单价           : 6.00 CNY
数量           : 10
--- 兑换码（只显示这一次，请立刻保存） ---
JEV-7K2M-9XQ4-...
```

**码只在这一次输出里出现明文**，之后只能按批次查状态。如果丢了，
把该批次作废重新发一批即可（不会影响已兑换的码）。

商品版本不存在时脚本会按首发口径自动创建（月度 600 分 / 永久 2000 分）。

### 3. 交付

把码发给买家（微信/邮件/小红书私信都行）。买家在
`https://sp.xiaobaozi.cn/me` 的「开通会员」面板里粘贴兑换码，点「兑换」。

### 4. 对账

```bash
# 批次列表（发放数 / 已用数 / 未用数）
docker exec situation-puzzle-api-1 pnpm --dir apps/api exec tsx src/cli/issue-redeem-codes.ts --help
```

或用后台接口 `GET /api/v1/admin/redeem-codes/batches`（需管理员会话）。

## 码的规则

- 格式：`JEV-XXXX-XXXX-XXXX`，16 位基 32 熵（约 1.15e24 种组合）。
- 字母表去掉了 `I O 0 1` 等易混字符，人工转写不会认错。
- 用户输入时大小写、空格、连字符都容错（内部按「去分隔符 + 大写」归一化检索）。
- 一码一权：核销时对码行加 `FOR UPDATE` 行锁，并发兑换同一个码只有一个成功。
- 码状态：`unused` → `used` / `revoked`。已使用的码不可作废。

## 一致性保证

「码被吃掉但权益没发」是这个通道唯一致命的失败模式，因此：

- 码状态流转（`unused → used`）与赞助授权发放、订单核销、流水与审计日志
  **在同一个数据库事务里**提交，任一环节失败整体回滚；
- 权益只来自服务端：兑换成功后由服务端发放授权，前端只刷新 `/me`；
- 重复兑换返回「兑换码不存在／已被使用／已过期」，不产生第二笔订单。

## 常见问题

**Q：码发出去了但买家说兑换失败？**
A：先确认买家用的是「当前批次未使用的码」。已用、已作废、已过期都会失败。
后台 `GET /api/v1/admin/redeem-codes?batchId=<批次号>` 能看每个码的状态与使用者。

**Q：卖错价了怎么办？**
A：`POST /api/v1/admin/redeem-codes/revoke`（body：`{ code, reason }`）作废未使用的码，
重新发一批。已兑换的码需要人工退款，登记到 `refunds` 表走退款流程。

**Q：兑换码买的会员能退款吗？**
A：能，但**只能在管理后台退**（`POST /api/v1/admin/orders/:id/refund`，需 admin/finance 角色 + 理由），
玩家端没有退款入口。赞助码是线下收款，没有线上退款接口可调，
所以后台点完退款后**权益直接在站内撤销**（订单置 `refunded`）。
后台会提示「无线上退款步骤，权益已在站内撤销」。详见
[15-PAYMENT-CHANNELS.md](15-PAYMENT-CHANNELS.md#退款只在后台玩家端没有退款入口)。

**Q：能不能自动发码？**
A：目前是「人工收款 → 人工发码」一步。个人收款码没有支付回调，无法自动核销到账。
拿到微信商户资质后切到 Native 通道即可完全自动化，两条通道代码都在。

## 与微信支付共存的配置

微信通道在 `.env` 里补齐这组变量就会自动开启（适配器读不到就返回 null，
前台显示「支付通道开通中」）：

```
WECHAT_PAY_MCHID=
WECHAT_PAY_APPID=
WECHAT_PAY_SERIAL=
WECHAT_PAY_PRIVATE_KEY_PATH=
WECHAT_PAY_API_V3_KEY=        # 32 字节
WECHAT_PAY_NOTIFY_URL=https://sp.xiaobaozi.cn/api/v1/payments/wechat_native/notify
WECHAT_PAY_PLATFORM_PUBLIC_KEY_PATH=
```

注意：微信 Native 需要**公网可达**的回调地址。`sp.xiaobaozi.cn` 已备案并指向
自有服务器（国内），满足微信的回调要求。
