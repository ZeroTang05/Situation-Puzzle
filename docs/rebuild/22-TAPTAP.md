## 配置

服务器配置：

```dotenv
TAPTAP_MINI_APPID=tapmcmnlmv6v8lx5mb
TAPTAP_MINI_SECRET=填写小游戏密钥
```

两项同时配置才注册登录插件；只填一项在启动期报错。AppSecret、平台 session_key 不进入客户端。账号按 `taptap-mini + MiniApp ID:openid` 唯一识别，保留现有注册钩子初始化业务账户。

已有邮箱账号可先通过邮箱方式登录，再在设置里「关联当前 TapTap 账号」。已归属另一个站内账号的 TapTap 身份会明确拒绝关联，不自动合并账号。

已有 Google / LINUX DO / 邮箱账号还可以使用「官网账号登录」：

1. 小游戏请求 Better Auth `deviceAuthorization`（设备授权）插件，显示确认码并提供公开授权链接。
2. 玩家在浏览器打开官网 `/device?user_code=…`；未登录时先去现有登录页，成功后返回确认页。
3. 确认页显示当前账号与确认码，玩家点击「允许登录」或「拒绝」。
4. 小游戏在前台每五秒查询一次；允许后取得本站 Bearer 会话，进入原有账号。后台暂停查询。

设备秘密 `device_code` 只保存在小游戏内存，不放链接、不打印、不持久化。确认码十分钟有效；取消或离开页面后停止查询。服务器限定小游戏 client ID，拒绝调用者预先指定账号；实际账号由登录后的确认页认领。凭证只允许兑换一次。实现复用当前 Better Auth 1.7.6 插件的随机数、状态流转和一次性消费。

部署需同时更新 web 和 API，并应用追加式迁移 `0018_device_authorization.sql`，新增 `device_code` 表。设备授权插件与平台登录一样，只在服务器配齐 TapTap 两项凭据时启用。
