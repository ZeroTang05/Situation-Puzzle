# Jev 多人海龟汤：开发文档入口

版本：1.0；更新日期：2026-09-26；现有代码基线：`d4fd1e4`。

这套文档把单人网页游戏改造成可收费的多人产品。第一阶段交付浏览器版本，前后端部署到自有服务器；后续小程序和 App 共用服务端能力。本轮只编写文档，尚未执行代码迁移、部署或真实支付验证。

## 给开发模型的执行约定

1. 先读全部文档，再按 MVP 的阶段交付。产品规则以 PRD 为准，接口与状态以 SPEC 和房间协议为准；发现冲突先修正文档，再实现相关功能。
2. 本文档中的数值分为“首发设计默认值”“待实测目标”“待商业确认”。默认值可以用于实现；待实测目标必须用结果验证；待商业确认项不得自行当作已获用户批准。
3. 先做一次真实 Jev 调用、真实登录通道和目标服务器探测。外部通道尚未具备时，记录阻塞，继续不依赖它的模块；正式产品禁止用假成功替代真实通道。
4. 多人房间和商业状态写入数据库。单人对话、进度与提示状态只存浏览器，本平台服务端不保存单人对话或可关联个人的游玩记录。
5. 每阶段交付可运行结果、相关测试证据和操作说明。需要人工体验的功能等待项目负责人确认后再提交代码，遵循仓库现有约定。
6. 旧系统保持可运行，直到新系统达到切换条件。删除清单表示目标终态，删除时机见迁移文档。
7. 实现时生成并提交 OpenAPI（HTTP 接口描述）、事件 JSON Schema（消息结构约束）、数据库迁移、环境变量模板及部署说明。这里的表格是这些文件的设计依据，不表示已有可执行接口。

## 当前采用的产品方案

房主创建最多 8 人的私密房间，邀请朋友共同推理；每一局固定一道题，同一房间可连续换题。所有成员可提问和提交推理，Jev 按队列处理。单人模式无需登录，永久免费且不限次数，对话只存本地。两种模式共用题库与 Jev 判题服务，各自处理状态和记录存储。

用户已确定：面向中国大陆、国内自有服务器、邮箱验证码与 Google 授权登录。未赞助账号累计可开 10 个多人房间；月度赞助 6 元，永久赞助 20 元，赞助有效时不限开房次数。全部用户单人游玩和单局提问无限制，朋友加入多人房间免费。

一个多人房间只计一次，同房间换题不重复扣次；空房取消不扣次，第一次有效判题确认消费。首发默认主动付款续期。服务器具体配置、支付商户开通、邮件服务和 Google 应用凭据见决策清单。

首发完成商业闭环：用户能付款获得赞助权限、正常开房、在故障时得到处理，运营能审核题目、处理举报、查询订单和办理退款。目前没有支付商户资质，通道就绪前只发布不收款的测试版。小程序、App、作者分成放在后续阶段。
