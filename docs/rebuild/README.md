# Jev 多人海龟汤：开发文档入口

版本：1.1；更新日期：2026-10-01；现有代码基线：`50e60d6`。

这套文档把单人网页游戏改造成可收费的多人产品。第一阶段交付浏览器版本，前后端部署到自有服务器；后续小程序和 App 共用服务端能力。本轮只编写文档，尚未执行代码迁移、部署或真实支付验证。

## 给开发模型的执行约定

1. 先读全部文档，再按 MVP 的阶段交付。产品规则以 PRD 为准，接口与状态以 SPEC 和房间协议为准；发现冲突先修正文档，再实现相关功能。
2. 本文档中的数值分为“首发设计默认值”“待实测目标”“待商业确认”。默认值可以用于实现；待实测目标必须用结果验证；待商业确认项不得自行当作已获用户批准。
3. 先做一次真实 Jev 调用、真实登录通道和目标服务器探测。外部通道尚未具备时，记录阻塞，继续不依赖它的模块；正式产品禁止用假成功替代真实通道。
4. 多人房间和商业状态写入数据库。单人对话、进度与提示状态只存浏览器，本平台服务端不保存单人对话或可关联个人的游玩记录。
5. 每阶段交付可运行结果、相关测试证据和操作说明。需要人工体验的功能等待项目负责人确认后再提交代码，遵循仓库现有约定。
6. 旧系统保持可运行，直到新系统达到切换条件。删除清单表示目标终态，删除时机见迁移文档。
7. 实现时生成并提交 OpenAPI（HTTP 接口描述）、事件 JSON Schema（消息结构约束）、数据库迁移、环境变量模板及部署说明。这里的表格是这些文件的设计依据，不表示已有可执行接口。

## 当前采用的产品方案

房主创建最多 8 人的私密房间，邀请朋友共同推理；一个房间只玩一道题。结束后可创建新房并一键迁移原房合格成员，两个房间分别保存记录。所有成员可提问和提交推理，Jev 按队列处理。单人模式无需登录，永久免费且不限次数，对话只存本地。两种模式共用题库与 Jev 判题服务，各自处理状态和记录存储。房间生命周期修订见 [10-ROOM-LIFECYCLE-REVISION.md](10-ROOM-LIFECYCLE-REVISION.md)。

用户已确定：面向中国大陆、国内自有服务器、邮箱验证码与 Google 授权登录。未赞助账号累计可开 10 个多人房间；月度赞助 6 元，永久赞助 20 元，赞助有效时不限开房次数。全部用户单人游玩和单局提问无限制，朋友加入多人房间免费。

一个多人房间只计一次；下一题创建新的房间并重新检查开房资格。空房取消不扣次，第一次有效判题确认消费。房间离线后可继续，不按闲置时间自动归档。首发默认主动付款续期。服务器具体配置、支付商户开通、邮件服务和 Google 应用凭据见决策清单。

首发完成商业闭环：用户能付款获得赞助权限、正常开房、在故障时得到处理，运营能审核题目、处理举报、查询订单和办理退款。目前没有支付商户资质，通道就绪前只发布不收款的测试版。小程序、App、作者分成放在后续阶段。

## 1.1 文档与实现的最新对齐（2026-10-01）

本轮文档与代码同步的关键变更（详见对应章节）：

- **题目难度** 由文本字段收紧为 `puzzle_difficulty` 枚举（easy / medium / hard）；契约、数据库、列表与单人都按枚举取值。详见 [03-SPEC §5.1 / §6](03-SPEC.md#51-身份与内容)。
- **作品提示** 由「必须填三条」放宽为「提示 1 必填、提示 2-3 可选」；提交时仍要求至少一条提示，且空字符串不入库。详见 [03-SPEC §6 / §9 §4](03-SPEC.md)。
- **创作中心** 引入字段级校验：zod 错误直接定位到出错字段，自动滚动并聚焦首个错误；表单输入框内不展示提示文字，控件渲染 `aria-invalid`。详见 [03-SPEC §9](03-SPEC.md) 与 [09-IMPLEMENTATION §4](09-IMPLEMENTATION.md)。
- **私人试题预览** 与单人游玩共用顶部栏、题面卡、聊天、操作行与 `ChatInput`，仅复用 `/solo/*` 服务端接口但对话只存本地。详见 [08-SOLO §2](08-SOLO.md)。
- **作品内单选控件** 使用自定义 `Segmented`（分段按钮组），替代原生 `<select>`，避免 Android 上的原生选择弹窗；仅用于选项 ≤3 的场景。
- **创作列表与「我的」** 改为扁平行项（无圆角矩形框、无卡片边框、淡分割线分组），与创作编辑面板共享设计语言。
- **Auth 页内联超链接** 默认浅蓝色（`#8fc6ff`）+ hover 下划线；语言切换按钮除首页外，也出现在登录、注册、找回密码页的 topbar 右侧。
